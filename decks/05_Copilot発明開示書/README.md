# Copilotで作る発明開示書

## 目的

ANAQUA形式の発明開示書を、Copilotで素案まで作る手順を説明する。
5枚目は最終の章立て、6枚目は作業順。先行特許は2回見る。図はCopilotの中だけで作る。

## 今回の直し

| コメント | 反映 |
|---|---|
| 以前との違いがいらない | 対比の説明をやめ、いまの進め方だけにした |
| AIの解答例が短すぎる。本当の回答を | 各StepにGrokが返す長さの回答例を載せた |
| 「先行」を「先行特許」に | 用語を先行特許にそろえた |
| 「終わったら」はゴールの意味に | 手順図の見出しを「ゴール」にした |
| 6枚目の①と④だけオレンジ | 番号の色をすべて紺にそろえた |
| PatentSQUAREは上級者向け。まずはCopilotで先行特許調査でもよい | 道具はCopilotが主。PatentSQUAREは社内ツールとして任意に記載 |
| page5の「この順で埋めていく」とpage6の手順が迷う | 5枚目は最終の章立て、6枚目は作業順、と分けた |
| 先行特許調査が2回ある役割を明示 | Step1は背景と方向性。Step4と5の間は衝突確認。衝突ならStep2へ戻る |
| PatentSQUAREの出番はStep4と5の間 | 衝突確認のページに置き、使い方は書かず参考リンクだけ |
| 各Stepの回答例は①。③の仕上げも見せたい | 各Stepの後ろに仕上げ（③）ページを追加 |
| Graphvizは外部リンクをやめ、Copilotだけで作る | 方針・聞き方・図1〜4の例を展開。社外ツールは使わない |
| 例をプロセス開発高速化ツールに | ①②③と図を、提出済み開示書の内容に差し替えた |
| 仕上げ③はANAQUAに入れる分量に | 技術分野・調査・構成・効果・クレームを本文量で載せた |
| Graphvizの図は開示書の処理フローを参考に | 図1従来フロー、図2システム構成、図3処理フローチャート |

## 概要

- 対象: 初めて発明開示書を書く人
- 枚数: 27（16:9）
- 例の発明: プロセス開発高速化ツール（ANAQUA開示書を参考）
- 回答例: ①60点の素案。仕上げ③はANAQUAに入れる分量

## スライド構成

| # | 内容 |
|---|---|
| 1 | 表紙 |
| 2 | この資料で伝えたいこと |
| 3 | 使う前の約束（セキュリティ／AIは支援者） |
| 4 | 道具（Copilotが主。PatentSQUAREは4と5の間） |
| 5 | 最終の章立て（ANAQUA）。書き順ではない |
| 6 | 本マニュアルの作業順 |
| 7 | 先行特許は2回見る |
| 以降 | Step 0〜5（説明＋①、その直後に③仕上げ）。4と5の間に衝突確認 |
| 末尾 | 図はCopilotの中だけで作る（方針・聞き方・図1従来／図2構成／図3処理） |

再生成: `python3 generate_invention_disclosure.py`

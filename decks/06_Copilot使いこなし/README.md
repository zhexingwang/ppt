# Copilotとのやり取りのコツ

## 目的

発明開示書マニュアル（`decks/05_Copilot発明開示書`）を使う側から、チャットの使い方がまだ揃っていない、という声があった。目的の違う作業を同じチャットで続け、生成結果が混ざる。依頼の言葉も短い。

このデッキは、手順そのものではなく、Copilotへ頼む前の使い方をリストにしたもの。対象は、発明開示書、特許文書、特許の図。

## 伝えていること

- 同じチャットは、前の発言を読んだうえで答える。目的が変わったら新しく開く。モデルが発明を学習して覚える、という意味ではない。
- 発明が一つでも、本文・先行特許・クレーム・図・レビューは分ける。図は従来と本発明でも分ける。
- チャットを移すときは、全文を貼らず、確定したことだけを持っていく。
- 最初に、作業、成果物、事実、守ること、出力の形を書く。数値・実施例・文献番号は作らせない。
- 一度に頼むことは一つ。直す箇所は引用で指定する。
- 図は、箱と符号の表を確定してから専用チャットで作る。社外の作図サイトには出さない。
- 例は、手順編と同じ「プロセス開発高速化ツール」。独立項の範囲も手順編に合わせ、選定や理由の出力は従属項に回している。

# Copilotとのやり取りのコツ

## 目的

発明開示書マニュアル（`decks/05_Copilot発明開示書`）を使う側から、チャットの使い方がまだ揃っていない、という声があった。一つの特許を書いているあいだに、目的の違う作業を同じチャットで続け、生成結果が混ざる。依頼の言葉も短い。

このデッキは、手順そのものではなく、一つの発明を開示書・特許文書・図にするときの頼み方をリストにしたもの。別の特許との取り違えを扱う資料ではない。

## 伝えていること

- 同じチャットは、前の作業を前提に答える。作業が変わったら新しく開く。モデルが発明を学習して覚える、という意味ではない。
- 一つの特許の中で、本文・先行特許・クレーム・図・見直しは分ける。従来の図と本発明の図も分ける。
- 次の作業へ移るときは、全文を貼らず、決まったことだけを渡す。
- 最初に、作業、成果物、事実、守ること、出力の形を書く。数値・実施例・文献番号は作らせない。
- 一度に頼むことは一つ。直す箇所は引用で指定する。
- 図は、処理の段階と符号の表を決めてから専用のチャットで作る。社外の作図サイトには出さない。
- 例は、手順編と同じ「プロセス開発高速化ツール」。独立項の範囲も手順編に合わせ、選定や理由の出力は従属項に回している。
